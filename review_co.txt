# **Detecting Spurious Features via Intervention-Based Performance Sensitivity:** 新規性と粗の整理

まず、このドラフト単体としては「論文になりうる水準」の新規性は十分あります。

## **新規性の核**

- **問題設定のズレ取り**
  既存は「スプリアス抑制のために学習アルゴリズムを変える」か、「SHAP/LIME等で寄与度を測る」ライン。
  ここでは「**候補特徴は別手法に任せ、その後段で“本当に性能に効いているか”だけを定量確認する PerformanceCheck を定式化**」しており、パイプラインの**後半ステップの形式化**が明確に新しいです。
   (, 2026)- **指標の定義と比較設計**
  「破壊的介入による性能差 Δ」で依存度を直接定義し、GridWorld・ColoredMNIST・Waterbirdsで**同一オラクル・同一シードでSHAPと系統比較**している点は、Adebayo らよりも踏み込んだ定量比較になっています。
   (, 2026)- **具体的な新知見**
  - GridWorld で、Δ は top-1 71% vs SHAP 12% と、大差でスプリアス検出が良い
  - ColoredMNIST での「SHAP 120/120 は構造的アーティファクト」という解析
  - Waterbirds で、実世界寄り条件で Δ と SHAP の一致と乖離を丁寧に分解
  いずれも「**寄与度ベース帰属と性能ベース介入の乖離を、具体的データで見せた**」点が貢献。
   (, 2026)## **強み**

- **位置づけが明確**：Related WorkとDiscussionで、「発見ステップ vs 確認ステップ」「representation-space proxy vs input intervention」の役割分担をかなり丁寧に書けている
   (, 2026)- **負例の扱い**：LunarLander を「フレームワークの適用限界を示す例」としてきちんと位置づけているのは好印象です。
   (, 2026)## **粗・改善余地（論文として見たときの不安点）**

### 1. スコープ・メッセージの絞り方

今の Draft はかなり多機能に見えます：

- 「スプリアス検出ベンチとしての Δ vs SHAP 解析」
- 「発見手法とのパイプライン全体像」
- 「Waterbirds での worst-group accuracy 再集計」
- 「Spec/PCA proxy との比較」

読み手からすると「結局何が一番のメッセージ？」が少し散らかって見えます。
Conclusion 近辺を以下のように**一本化**した方が通りやすいです：

- 主張1：**性能ベース介入（Δ）は、寄与度ベースよりも“本当に効いている”スプリアスを絞り込める**（GridWorld, Waterbirds）
- 主張2：**一部の合成ベンチでは、データ符号化×集約則がSHAPを“偽のオラクル”にしてしまう具体例を示した**（ColoredMNIST）
- 主張3：**Δは発見手法/hidden-space proxyの“フィルタ”として機能し、パイプライン後段の役割を持つ**

### 2. 実験デザインの「一貫した問い」へのマッピング

今のままでも情報は十分ですが、査読者視点では：

- 各実験が「どの仮説を検証しているのか」が見えるとかなり読みやすくなります
  - 例：Exp016/017 = H1（Δはspurious_p増大でどのように振る舞うか）
  - Exp018 = H2（実世界寄り条件でもΔは有効か）
  - Exp021 = H3（representation proxyとfunctional necessityは系統的にずれるか）

小節タイトルやResultsの冒頭で「Hypothesis/Question」を一言入れると、格段に通りがよくなります。

### 3. 限界と今後の展望の「次の一歩」明示

Limitationsは充実していますが、「では次に何をすべきか」が少し分散しています。
PerformanceCheck の次ステップとして：

- 介入設計の自動化・標準化（今後あなたがやりたいところ）
- 候補列挙との結合（Neuhaus/Eyuboglu/Sohoni等との統合実験）

を2〜3行で「Future Work」としてまとめておくと、シリーズものの1本目としてきれいに見えます。

## **結論：**

- 新規性：**あり**。特に「介入ベースの性能感度による後段確認ステップの定式化＋SHAPとの大規模比較」は、単なる応用ではないレベル。
- 粗：
  - メッセージがやや多いので、「Performance-based confirmation step」として一本化するとよい
  - 各実験の役割（どの仮説を担っているか）を明文化すると、論文としての筋が通りやすい

このままブラッシュアップすれば、ワークショップ〜本会議下位帯レベルなら十分狙える内容に見えます。
