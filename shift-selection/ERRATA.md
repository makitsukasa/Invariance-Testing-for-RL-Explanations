## 1. exp011・exp016 の SHAP の集約の誤り（2026-10-25 に発見）

### 何が誤っていたか
`experiments/run_shap_psweep.py` の `_compute_shap_ranking`（84 行目）は、`shap_values` が配列で返ったとき、特徴の重要度を次のように集約している。

```python
arr      = np.abs(np.array(shap_vals, dtype=float))
mean_abs = arr.reshape(-1, n_features).mean(axis=0)
```

shap 0.51 の `KernelExplainer` は、多出力のモデル（DQN の 4 行動の Q 値）に対して、形 (サンプル, 特徴, 出力) = (300, 10, 4) の配列を返す。これを `reshape(-1, 10)` すると、特徴の軸と出力の軸が混ざる。平坦化した添字は `40·s + 4·f + o` なので、列 j には `(4f + o) mod 10 = j` を満たす (特徴 f, 行動 o) の組が集まる。c（f = 2）の寄与は「agent_x」「agent_y」「noise_5」「noise_6」とラベルされた列に入り、「c (spurious)」とラベルされた列には c の寄与が一切入らない。

### どう確かめたか（exp029）
`experiments/run_shap_delta_2x2.py`（exp029）で、exp016 と同じ設定・同じ seed・同じ乱数の順序で再実行した。

- AA、J_S_train、サロゲートの Δ（全 10 特徴）は、120 件すべてで exp016 の `results.csv` と一致した（最大絶対差 0）。
- exp029 の SHAP の値に上の集約をそのまま適用した値は、120 件すべてで exp016 の `shap_*` 列と一致した（最大絶対差 0）。
- 同じ SHAP の値を、評価サンプルと出力の軸について正しく平均した値は、exp016 の列と一致しない（最大絶対差 0.126）。

照合の詳細は `experiments/results/exp029_shap_delta_same_model/stats.txt` の「exp016 との照合」にある。

### 正しく集約したときの結果（exp016 と同じ 120 run、オラクルの Q 値に対する SHAP）

| p | exp016 の SHAP@1（誤った集約） | 正しい集約の SHAP@1 | c がノイズ特徴 7 個すべてを上回った数（正しい集約） |
|---|---|---|---|
| 0.0 | 0/30 | 30/30 | 30/30 |
| 0.1 | 2/30 | 7/30 | 30/30 |
| 0.2 | 4/30 | 6/30 | 27/30 |
| 0.3 | 8/30 | 11/30 | 26/30 |
| 全体 | 14/120 | 54/120 | 113/120 |

正しく集約すると、SHAP が c を top-1 に選ばなかった 66 件は、すべて位置の特徴（agent_y 34 件、agent_x 32 件）を選んでいた。

### exp011 について
exp011 は同じスクリプト（`run_shap_psweep.py`）と同じ shap の設定を使っており、同じ集約の誤りを含む。exp011 と exp016 で共通の seed 0 では、exp011 の README の値（p = 0.0 で SHAP_c = 0.0207、選択 agent_y）が exp016 と一致する。exp011 の他の seed（42・123・456・789）は再実行していない。

## 2. 主張2の一部撤回（2026-10-25）

### 変更前
「どの特徴をシフトすべきかは、特徴ごとに介入したときの性能低下 Δ で選べる。SHAP では c がノイズと区別できない。」

### 変更後
「どの特徴をシフトすべきかは、特徴ごとに介入したときの性能低下 Δ で選べる。」を維持し、「SHAP では c がノイズと区別できない」を撤回する。SHAP と Δ は測定対象が異なるため、Δ が一般に SHAP より優れているとは主張しない。

### 理由
exp029 で、正しく集約した SHAP は、オラクルで 113/120、サロゲートで 106/120 の run で c をすべてのノイズ特徴より上位に置いた。「ノイズと区別できない」は exp016 の集約の誤りによるものだった。

### exp029 で示されたこと
- GridWorld 10 次元（候補特徴は与えられている、c は二値、介入は一様分布 [0,1] での置換）で、同じモデル上で比べても、Δ の順位は mean |SHAP| の順位より c を top-1 に置くことが多い（サロゲート 85/120 vs 43/120、オラクル 108/120 vs 54/120、McNemar とも p < 0.0001）。差は p ≥ 0.1 で生じ、p = 0.0 では両者とも 30/30。
- SHAP が c を外すのは、ノイズ特徴ではなく位置の特徴を c より上位に置くため。

### どこまで一般化できないか
- SHAP（予測値と背景の期待値の差の加法的配分）と Δ（介入したときの性能低下）は別の量を測る。exp029 が示すのは、この設定で「シフトしたとき性能が崩壊する特徴」を選ぶという目的に対して、Δ の順位の方が合っていたことであり、SHAP の説明としての妥当性を評価したものではない。
- 1 つの環境、1 つの介入（一様置換）、SHAP の 2 種類の集約（全行動の平均、予測行動のみ）、KernelExplainer の近似（nsamples = 100）に限られる。
- ColoredMNIST（exp017）と Waterbirds（exp018）では、それぞれの集約の規則のもとで SHAP の検出率が Δ を上回っており、手法の優劣の向きは設定によって異なる。
- Δ の結果はモデルにも依存する（オラクル 108/120、サロゲート 85/120）。

### 未解決
- 草稿（`draft.md`・`draft_short_en.md`）の該当箇所の書き直し。統合した論文の新しい草稿で行う。

- ColoredMNIST の SHAP の集約が、コメントと異なり 2 クラス分を平均していることの影響の確認。

## 4. 主張2の正解の定義を直接検証していなかった（2026-10-25 に発見）
主張2の正解は「選んだ特徴をシフトしたとき、実際に性能が崩壊するか」だが、既存の実験はこれを直接測っていない。
- exp011・exp016・exp029 の正解は「c を top-1 に置いたか」で、c がスプリアスであることは環境の設計から与えたもの。
- exp005 の Stage 2 は、選定の結果によらず常に c を反転していた（5 シード）。

選定と評価を独立させた検証は exp030 で行う（設計：`experiments/plans/exp030_shift_target_validation.md`）。
