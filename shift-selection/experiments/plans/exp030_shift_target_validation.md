# exp030 の設計：選定と評価を独立させた、シフト対象の選定の検証（実行前の事前登録）

この文書は実行前に書き、コミットしてから実行する。判定条件は結果を見てから変えない。実装の誤り（シフト演算子のバグなど）が見つかって直した場合は、直した内容をこの文書の末尾に追記し、判定条件はそのまま使う。

## 1. 研究の問い（変更しない）
主張2：「どの特徴をシフトすべきかは、特徴ごとに介入したときの性能低下 Δ で選べる。」

この実験では、主張2の正解の定義「選んだ特徴をシフトしたとき、実際に性能が崩壊するか」を直接確かめる。あわせて、主張1（不変性テスト）と主張2（Δ による選定）をつないだ診断手順全体が、スプリアス依存を検出できるかを評価する。

## 2. 既存の根拠の問題
- exp029 の正解は「c を top-1 に置いたか」で、c がスプリアスであることは環境の設計から与えたものだった。選んだ特徴をシフトしたら崩壊するかは測っていない。
- exp005 の Stage 2 は、選定の結果によらず常に c を反転していた（5 シード）。
- Δ は「特徴を一様分布 [0,1] で置換したときの性能低下」そのものである。Δ で選んだ特徴に同じ置換をして性能低下を確かめても、選定の基準で評価することになり、検証にならない（循環）。

## 3. 設計

### 3.1 モデルと選定（exp029 と同じ 120 run）
- 設定は exp029 と同じ（GridWorld 10 次元、`spurious_p` ∈ {0.0, 0.1, 0.2, 0.3}、seed 0〜29、DQN 50,000 ステップ、SoftMoET 4 専門家・深さ 5）。
- オラクルとサロゲートを同じ seed で再学習する。exp029 は exp016 を完全に再現したので、学習は決定的に再現できる。再現の確認として、AA と J_S_train が exp029 の `results.csv` と一致することを確かめる（一致しなければ実行を止めて報告する）。
- 選定には exp029 の `results.csv` に記録済みの順位を使う。つまり、選定はこの実験の評価より前に確定しており、評価の結果を見て選定を変えることはできない。

| 選定法 | 内容 | 位置づけ |
|---|---|---|
| Δ（サロゲート） | exp029 の `delta_sur_*` の最大の特徴 | **主な比較対象**。不変性テストの対象はサロゲートなので、サロゲートから計算した選定を主とする |
| SHAP（サロゲート） | exp029 の `shap_sur_*`（全行動の mean \|SHAP\|）の最大の特徴 | Δ（サロゲート）と同じモデル・同じ条件の比較 |
| Δ（オラクル）・SHAP（オラクル） | exp029 の `delta_ora_*`・`shap_ora_*` | 副次的な比較 |
| ランダム | 10 特徴から一様に 1 つ選ぶ | 比較の基準。期待値（下記）で評価し、固定 seed での 1 回の抽選も参考に記録する |

### 3.2 評価：環境側の分布シフト（Δ の置換とは別の操作）
各 run の **10 特徴すべて** について、下の分布シフトを適用した環境でサロゲートとオラクルを評価する。どの選定法が選んだかによらず全特徴を評価するので、評価は選定から独立している。

| 特徴 | シフト（各 2 種類） | 意味 |
|---|---|---|
| c | `reversed`：c = 1 − goal_id。`random`：c ~ Bernoulli(0.5)（ゴールと無関係） | 既存の `SpuriousGridWorld` の `eval_mode` をそのまま使う。論文A 実験2と同じ |
| noise_i（7 個） | `low`：noise_i ~ U(0, 0.5)。`high`：noise_i ~ U(0.5, 1)。他の特徴はそのまま | その特徴の周辺分布だけを変える |
| agent_x | 開始位置の x を {0, 1} に限る / {3, 4} に限る | 初期状態の分布だけを変える。観測値は書き換えない |
| agent_y | 開始位置の y を {0, 1} に限る / {3, 4} に限る | 同上 |

Δ の置換とは次の点で異なる。
- Δ は観測値を毎ステップ書き換える（c は {0,1} の外の連続値になり、位置は実際の位置と食い違う）。評価のシフトは環境のデータ生成過程を変え、観測は環境の状態と矛盾しない。
- Δ は c について「訓練分布の外の値」を入れるが、評価のシフトは c を {0,1} に保ったままゴールとの関係だけを変える。
- noise は毎ステップ U(0,1) から独立に引かれるので、Δ の置換は noise の分布を変えない。評価のシフトは noise の周辺分布を変える。

既存の環境ファイルは変更せず、シフト用の環境は新しいスクリプトの中でサブクラスとして定義する。

### 3.3 正解（特徴ごとの判定）
評価の乱数は Δ・SHAP の乱数と重ならない seed を使う（エピソードの seed：`seed + 100,000 + 条件番号 × 1,000`）。各条件で
- J_S(shift)：サロゲートの平均リターン（500 エピソード）。
- J_O(shift)：オラクルの平均リターン（同じ 500 エピソード）。
- AA(shift)：シフトした環境でオラクルを走らせて集めた 2,000 状態での、オラクルとサロゲートの行動一致率。
- 基準値 J_S(train)・AA(train) も同じ seed の体系で、シフトなしの環境で測り直す。

特徴 k の判定（2 種類のシフトのどちらかで成り立てば、k はその判定で「崩壊する特徴」）：
- **G_J（性能の崩壊）**：J_S(shift) < 0.8 × J_S(train)。主張2の正解の定義そのもの。**選定の評価の主な正解**とする。
- **G_inv（主張1の判定基準）**：AA(shift) > 0.9 かつ J_S(shift) < 0.8 × J_S(train)。論文A の判定基準（θ_AA = 0.9、α = 0.8）をそのまま使う。診断手順全体の評価に使う。

run r の正解集合を H_J(r)、H_inv(r) と書く。J_S(train) ≤ 0 の run は比が定義できないので、判定から外して件数を別に報告する。

### 3.4 診断手順全体（主張1と主張2をつないだもの）
実務で手順を使う場合を想定して、正解とは別の seed（`seed + 200,000 + 条件番号 × 1,000`、200 エピソード、AA は 2,000 状態）でもう一度テストし、手順の判定にはこちらを使う。
1. 段階1：AA(train) ≥ 0.9 を確かめる（論文A の段階1）。
2. 選定法で特徴を順位づけ、top-1 の特徴を 3.2 の 2 種類のシフトでテストする。
3. G_inv の基準で判定する（どちらかのシフトで成り立てば「スプリアス依存の疑い」）。

run r で手順が成功したとは、3 で「疑い」と判定し、かつその特徴が正解（3.3 の 500 エピソード）でも H_inv(r) に入っていること。段階1 で止まる run の扱いは、(a) 論文A の手順どおり段階1 で止める、(b) 段階1 を外す、の両方で報告する（主な結果は (a)）。

### 3.5 Δ と不変性テストの区別
同じ run・同じ特徴について、Δ（置換による性能低下）と、シフトによる性能低下 J_S(train) − J_S(shift) を並べて記録し、次を報告する。
- Δ の top-1 が H_J に入らない run と、そのときに選ばれた特徴。
- 特徴ごとの Δ とシフトによる低下の順位相関（run ごとの Spearman の分布）。
- 置換では大きく下がるがシフトでは崩壊しない特徴、またはその逆があるか。

## 4. 評価指標
- **hit@1**：選んだ特徴が正解集合に入っている run の割合（分母は正解集合が空でない run）。Wilson 95% CI。
- **hit@2**：上位 2 特徴のどちらかが正解集合に入っている割合。
- **検出までのテスト回数**：順位どおりに特徴をシフトしていって、最初に正解集合の特徴に当たるまでの回数。ランダムの期待値は (n+1)/(|H|+1)（n = 10）。
- **ランダムの期待値**：run r でランダムが当たる確率は |H(r)|/10。hit@1 の期待値はその和。
- **手順の成功率**（3.4）と誤った警告の率（手順は「疑い」と判定したが、正解では H_inv に入らない）。
- すべて p ごとと全体で報告する。

## 5. 判定条件（事前登録）

### 主な仮説（Holm 補正、有意水準 0.05、片側）
- **H1（選定）**：Δ（サロゲート）の hit@1（G_J）は、ランダムの期待値より大きい。検定は、run ごとに当たる確率が |H_J(r)|/10 のポアソン二項分布による正確検定。
- **H2（手順全体）**：診断手順（3.4、段階1 あり）の成功率は、Δ（サロゲート）で選んだ場合の方が、ランダムに選んだ場合の期待値より大きい。検定は H1 と同じ方式。run ごとにランダムが成功する確率は、「手順用の再テストで疑いと判定され、かつ H_inv(r) に入る特徴」の数 / 10。段階1 で止まる run は両者とも失敗として数える。

判定：
- H1 が棄却されれば、「この設定では、Δ で選んだ特徴は、環境側のシフトで実際に性能が崩壊する特徴に、偶然より多く当たる」とする。棄却されなければ、この設定では主張2を支持しないと報告する。
- H2 が棄却されれば、「この設定では、Δ による選定と不変性テストをつないだ手順は、ランダムに選ぶより多くスプリアス依存を検出する」とする。棄却されなければその旨を報告する。
- H1 と H2 の結果は、どちらの方向でも主張2の文言を後から変える根拠にはしない。結果は主張2を「支持する／支持しない」の形で報告し、文言の扱いはユーザーの判断を仰ぐ。

### 副次的な結果（判定条件は置かず、数値をそのまま報告する）
- Δ（サロゲート）と SHAP（サロゲート）の hit@1 の McNemar 検定。オラクル側の同じ比較。Δ が上回っても下回っても、SHAP に対する一般的な優劣の主張には使わない。
- hit@2、検出までのテスト回数、p ごとの結果、段階1 を外した手順の成功率。
- G_inv を正解にした場合の hit@1。
- 3.5 の Δ とシフトの比較。

### 先に書いておく、結果の解釈が変わる場合
- H_J(r) が c だけになる run が大半なら、この実験は「c を選んだか」を実測で確かめ直したものになる。そのとき H1 の結果は exp029 の c の検出率に近くなる。その場合も、正解を実測で決めたこと自体は exp029 との違いとして報告する。
- H_J(r) が空の run（どの特徴をシフトしても崩壊しない）は、選定法の失敗として数えない。件数を p ごとに報告する。
- 位置や noise のシフトで崩壊する run があれば、c 以外にも正解があることになり、ランダムの期待値も上がる。

## 6. 実行時間の見積もり
exp029 の実測（1 run あたり、オラクル学習 52 秒、サロゲート学習 5 秒、サロゲートのロールアウト約 14 ms／エピソード、オラクル約 7 ms／エピソード）から見積もった。

| 段階 | 1 run あたりの見込み |
|---|---|
| 学習（オラクル・サロゲート） | 約 57 秒 |
| 正解の評価（20 条件 × 500 エピソード × 2 モデル、AA 用の 2,000 状態 × 20） | 約 210 秒 |
| 手順用の再テスト（20 条件 × 200 エピソード × 2 モデル、AA 用の 2,000 状態 × 20） | 約 95 秒 |
| 合計 | 約 360 秒（崩壊してエピソードが 100 ステップまで伸びる run では長くなる） |

120 run を 4 並列で実行して、**約 3 時間（2.5〜4 時間）** の見込み。正解の評価を 300 エピソードに減らせば約 2.3 時間になるが、J の推定の標準誤差が大きくなるので、500 エピソードを推奨する。
